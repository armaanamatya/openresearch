# July 2026 — durable cloud and scheduler

## What changed

- Shifted from one-off cloud jobs toward durable, resumable reproduction
  campaigns with leases, fences, persistent state, and operator preflight.
- Added evaluation reporting, cost visibility, evidence integrity, and a
  single authoritative verdict path.
- Added scheduler foundations: ASHA-style shadow advisory, branch lineage,
  receipt-gated decisions, and later an authoritative scheduler runtime.
- Expanded cloud support across GKE, AKS, and experimental EKS paths while
  keeping each route feature-gated and operator-controlled.

## Decisions that still matter

- A submitted Kubernetes Job is not proof of durable execution. Ownership,
  lease renewal, pod readiness, persistent state, and fence generation all
  matter.
- Scheduler output is advisory until its evidence and authority gates are
  explicitly enabled. It must never adopt an LLM grade or bypass a terminal
  deterministic decision.
- Cloud spend, credentials, and capacity are preflight concerns. A code path
  existing does not mean it is safe or available to run.
- The final report must agree with authoritative evidence; stale UI/cost writes
  cannot overwrite a terminal result.

## Current posture

The platform has strong foundations but is still an operator-run research tool.
Keep new cloud or scheduler behavior default-off until tested against real,
reviewed run evidence.
