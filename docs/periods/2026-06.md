# June 2026 — execution and evidence

## What changed

- Hardened the RLM/SDK lifecycle against cancellation, teardown, and retry
  failures that could silently end or wedge a run.
- Introduced stronger metric, rubric, provenance, and evidence-gate behavior.
- Added first-class cloud execution work for GKE and AKS, plus provider and
  credential-routing seams.
- Added repo-first reproduction, allowing a paper’s referenced repository to
  be inspected and adapted while keeping it distinct from generated run code.
- Made lifecycle recovery, preflight, and failure classification more explicit.

## Decisions that still matter

- Fail closed on fabricated or unverified evidence; fail soft on optional
  observability and provider convenience features.
- Missing metrics, malformed reports, OOM, timeout, and capacity exhaustion
  must remain visible as distinct outcomes.
- Cloud backends share contracts but differ in credentials, storage, and job
  topology; do not flatten those differences into an untyped generic shell.
- Test environments must be hermetic: ambient `.env` values cannot determine
  default behavior or test results.

## Resulting boundaries

- `configs/papers/` contains per-paper constraints and targets.
- Provider selection is explicit through sandbox settings and preflight.
- Evidence receipts and deterministic checks sit between execution output and
  final verdicts.
