# backend/agents/rlm/CLAUDE.md

> Loaded when working in the RLM orchestrator. Root context: ../../../CLAUDE.md.

## The RLM orchestrator
`backend/agents/rlm/run.py` is the entry: builds `rlm.RLM(...)` (PyPI `rlms`) and calls `.completion()` on a worker thread. The paper is offloaded as the REPL `context` variable — the root sees only constant-size metadata (name, type, length), never the corpus (RLM Algorithm 1, arXiv 2512.24601).

Root writes Python calling primitives (`backend/agents/rlm/primitives.py`) via `custom_tools`. `PRIMITIVE_REGISTRY` binds **19** total — keep this count and `tests/rlm/test_registry.py`'s `EXPECTED` set in sync when adding a primitive:
- **12 core domain primitives:** `understand_section`, `extract_hyperparameters`, `detect_environment`, `build_environment`, `plan_reproduction`, `implement_baseline`, `run_experiment`, `verify_against_rubric`, `propose_improvements`, `record_candidate_outcome`, `check_user_messages` (root calls at start of each iteration), `respond_to_user` (pure file I/O + `user_message_response` SSE).
- **7 orchestration/aux primitives:** `heartbeat`, `recommend_next_tool`, `resolve_gpu_requirements` (dynamic-GPU), `codex_repair` (optional, default-off), `read_context_map` (PEEK-lite; returns `{}` unless `OPENRESEARCH_CONTEXT_MAP` is on), `inspect_repository` (repo-first; returns `{"status":"disabled"}` unless `OPENRESEARCH_USE_AUTHOR_REPO` is on), `consult_skill` (skill-library playbooks; returns `{"status":"disabled"}` unless `OPENRESEARCH_SKILLS` is on).

Root also calls `llm_query`/`rlm_query` (library built-ins) to navigate `context` slices. Verification is the `verify_against_rubric` primitive — called when the root judges useful; no fixed gate checkpoints. Run terminates via the library's `FINAL_VAR(<var>)` (no reserved `answer` variable). Time bounded three ways: `rlm`'s `max_timeout` (between iterations), per-primitive deadlines via `RunContext`, and a process-level wall-clock watchdog.

## File-backed run state, not a service
Each run is a **long-lived subprocess**. State in `runs/<project_id>/`:
- `demo_status.json` — UI status snapshot (atomic write)
- `rlm_state/` — per-iteration checkpoints; resume-safe
- `dashboard_events.jsonl` — append-only SSE event log
- `final_report.{json,md}` — benchmark output; carries `mode` (`rlm`|`rdr`), `models` (`{planner,executor,verifier,grader}` — verifier/grader null until the per-role picker lands), `started_at`, `completed_at`
- `cost_ledger.jsonl` — per-primitive USD spend
- `experiment_runs.jsonl` — every `run_experiment` result (logs, success, metrics)
- `code/` — the reproduced project
- `generated_rubric.json` — auto-derived rubric (arXiv runs without a vendored bundle)
- `repo/` — the paper's cloned official repository (pristine reference; orchestrator-host-only, never shipped to a GPU backend), when `OPENRESEARCH_USE_AUTHOR_REPO` is on
- `rlm_state/repo_spec.json` — the resolved RepoSpec + commit_sha (the deterministic trusted source `implement_baseline` + the report writer read)
- Hermes audit chain artifacts

SQLite (`OPENRESEARCH_DATABASE_URL`, canonical default `sqlite:///openresearch.db`) is the event/persistence store (CQRS projections); a `Settings` model-validator falls back to the legacy `sqlite:///reprolab.db` only when `openresearch.db` doesn't exist on disk but `reprolab.db` does (keeps pre-rename local installs/volumes working — an explicit `OPENRESEARCH_DATABASE_URL` always wins). Iteration state checkpointed atomically after each loop.

## RLM auth — two surfaces, billed separately
Two distinct LLM auth surfaces, NOT interchangeable:

1. **Root model** (`rlm` library, `_completion_turn` in `rlm/core/rlm.py`) talks raw HTTP. Pick one model + provide its credential:
   - `--model claude-oauth` → `claude` CLI subscription (macOS Keychain or `~/.claude/.credentials.json`, no API key)
   - `--model claude` → `ANTHROPIC_API_KEY` (Anthropic API credits)
   - default / `--model gpt-5` → `OPENAI_API_KEY`
   - `--model qwen3-coder` / `--model kimi-k2.5` → `OPENROUTER_API_KEY` (served via OpenRouter slugs in `models.py`)
   - `--model qwen3-coder-featherless` → `FEATHERLESS_API_KEY` (cheapest)
   - `--model azure` (aliases `azure-openai`, `gpt-4o-azure`) → `AZURE_OPENAI_API_KEY` + `AZURE_OPENAI_ENDPOINT` + `AZURE_OPENAI_DEPLOYMENT`
   - `--model opus-foundry` / `--model sonnet-foundry` → `AZURE_FOUNDRY_API_KEY` (real Claude weights via Foundry; see "Anthropic on Azure Foundry" below)
2. **Sub-agents** (`implement_baseline` + other Sonnet calls, via `claude-agent-sdk`) accept either `ANTHROPIC_API_KEY` *or* OAuth via the local `claude` CLI subscription (subscription path is per-message-free; API-key path is per-token-billed).

**Gotchas (rules):**
- A no-credit `ANTHROPIC_API_KEY` does NOT fall back to OAuth — the SDK hits `400 credit balance too low` and every run dies at the first Sonnet sub-call with `cost_usd=0.0`. Working `claude --print "ping"` proves only the *subscription*, not the *API key*. Safest local dev: leave `ANTHROPIC_API_KEY=` empty, `claude login` once, use OpenAI/Featherless for the root (or `claude-oauth` for both surfaces on the subscription). See `.env` lines 14–18.
- **Shell wins over `.env`.** Credential injection in `run.py` reads `os.environ` first, falls back to Settings — so a stale shell export of `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `OPENRESEARCH_RUNPOD_API_KEY` silently shadows `.env`. Workaround: prefix the CLI with `env -u OPENAI_API_KEY` (or unset). A warn-only shell-shadows-.env validator runs on the CLI reproduce path (`cli.py::_warn_on_shell_env_override`, 11 suspect keys — the four API keys + `OPENRESEARCH_RUNPOD_API_KEY` plus `AZURE_OPENAI_API_KEY`/`AZURE_OPENAI_ENDPOINT`/`AZURE_OPENAI_DEPLOYMENT` and `AZURE_FOUNDRY_API_KEY`/`AZURE_FOUNDRY_ENDPOINT`/`AZURE_FOUNDRY_DEPLOYMENT`, advisory); the server boot path still has none (BUG-LR-014 partially remediated).
- **Cheapest local-dev cost model:** OpenAI root (~$1/run via `--model gpt-5`) + OAuth subscription for Sonnet sub-agents ($0) + RunPod COMMUNITY GPU (~$0.34/run); no Anthropic API balance needed. Zero-cost: `--model claude-oauth` for both surfaces (subject to subscription rate limits). macOS OAuth detection probes the Keychain via `_has_claude_subscription_oauth()`.

**Root-model selection env var:** `OPENRESEARCH_RLM_ROOT_MODEL` ∈ `gpt-5`, `qwen3-coder`, `kimi-k2.5`, `claude`, `claude-oauth`, `azure-gpt-4o`, `azure-foundry` (alias `grok`), `opus-foundry`, `sonnet-foundry` — defaults to GPT-5 when `OPENAI_API_KEY` is set; falls back to `claude-oauth` when there are no API keys but `claude login` is active. An explicit `--model` overrides it.

## Per-role model selection (dynamic Sonnet/Opus ⇄ gpt-4/gpt-5)
`--models planner=<tok>,executor=<tok>,verifier=<tok>,grader=<tok>` (or `OPENRESEARCH_ROLE_MODELS='{...}'`, same vocabulary in JSON or `k=v`) points each of the **four roles** at a different model/provider in one place — canonical resolver `backend/agents/rlm/role_models.py::resolve_role_models` → `RoleSelection`. Tokens: `opus`/`sonnet`/`haiku` (Claude), `gpt-5`/`gpt-4o`/`o4-mini` (OpenAI-direct, `OPENAI_API_KEY`), `gpt-4o-azure`/`azure` (Azure OpenAI deployment, `AZURE_OPENAI_*`). The resolver **de-collapses** `opus`↔`sonnet` (the root alias table collapses both to `claude-oauth`=Sonnet; per-role selection must not). **Unset ⇒ byte-identical to single-provider today** — every sub-role inherits (executor→`_resolve_agent_runtime`, verifier→planner client, grader→`OPENRESEARCH_GRADER_*`). **API key ⇄ OAuth is seamless for Claude sub-roles:** a Claude verifier/grader pick auto-resolves OAuth-vs-API-key by availability via `grader_transport.resolve_anthropic_subrole_backend` (honours `llm_auth_strategy` — `oauth_only` always OAuth, `api_only` always key, `auto` prefers key when present else OAuth); the executor's `make_runtime("anthropic")` already SDK-auto-resolves the same way. `--models planner=X` drives the actual root model (`resolve_root_model`) when `--model` is unset, so the planner stamp matches what ran (explicit `--model` wins). Wiring: `run.py` builds the `RoleSelection`, a dedicated `ctx.verifier_client` (via `grader_transport.build_transport_client`) when verifier is overridden, an Azure-reachable executor runtime (`factory.make_runtime("azure")`), and feeds the unified grader pick into the existing `OPENRESEARCH_GRADER_*` env. **Rules:** executor is **unified-surface-only** — the legacy `OPENRESEARCH_EXECUTOR` flag keeps its own graceful-fallback path (routing it here would flip missing-creds → fail-fast); executor=azure fail-fasts on missing creds (critical), verifier=azure degrades to the planner client (non-critical); a non-Claude executor/verifier/grader on a hinted/fidelity-critical paper emits an advisory `role_model_fidelity` `run_warning` (never blocks — gpt-4o sub-agents are not SDAR-paper-validated). `final_report.models` stamps the resolved per-role `provider:model`. Code: `role_models.py` + `tests/agents/rlm/test_role_models.py`.

## Azure AI Foundry / Grok — one vocabulary across all FIVE tiers, fully OAuth-free
A generic **OpenAI-compatible custom endpoint** provider (`azure-foundry`, aliases `grok`/`foundry`/`grok-4.3`) makes any model deployed to a `*.services.ai.azure.com/openai/v1` endpoint usable for **every one of the five RLM LLM tiers** — root, executor, verifier, grader, and the navigation accelerator — so a run can be **fully OAuth-free** (grok root + grok/OpenAI sub-agents, no `claude` OAuth, no Anthropic key). All five tiers read the SAME canonical `resolve_foundry_credentials`: the navigation accelerator (`accelerator.py::_resolve_foundry`; modes `azure-foundry`/`foundry`/`grok` + an `auto`-chain pickup, `is_azure=False` so it rides `OpenAILlmClient`, no probe), the legacy `OPENRESEARCH_EXECUTOR` flag (`executor.py` `_FOUNDRY_MODES`, graceful-fallback-preserving — incomplete creds degrade to Sonnet, never fail-fast), `factory.selected_provider()` (names `azure`/`azure-foundry`/`grok` → the `"openai"` `ProviderName` literal), and `models.py` (root registry entry; Foundry base-url normalization delegates to the canonical resolver). Fully **dynamic + interchangeable**: the deployed model is whatever `AZURE_FOUNDRY_DEPLOYMENT` names — swapping it is a `.env` change, not a code edit. Env: `AZURE_FOUNDRY_ENDPOINT` (the `…/openai/v1` URL — auto-normalized from the bare resource or full `/chat/completions` paste), `AZURE_FOUNDRY_DEPLOYMENT` (e.g. `grok-4.3`), `AZURE_FOUNDRY_API_KEY`. Selection: `--model grok` (root) or `--models executor=grok,grader=grok,verifier=grok` (sub-roles), mixable with `gpt-5`/`sonnet`. Single source of truth: `backend/agents/runtime/foundry_endpoint.py::resolve_foundry_credentials` (os.environ → Settings/.env, normalized `(base_url, deployment, api_key)`) — the root registry (`models.py` `azure-foundry` entry), the executor runtime (`azure_foundry_runtime.AzureFoundryAgentRuntime` — OpenAI SDK base_url path, deployment as the model id), and the grader/verifier transport (`grader_transport` `azure-foundry` backend) all read it, never ad hoc. Distinct from the classic `azure-gpt-4o` root/`azure` provider (Azure OpenAI `/openai/deployments/{name}?api-version=`, `AsyncAzureOpenAI`, `AZURE_OPENAI_*`); Foundry is Bearer-auth OpenAI-compatible. `parse_model_spec` passes a root-only planner token through for stamping (`provider="root"`) instead of raising — `qwen3-coder`/`kimi-k2.5`/`qwen3-coder-featherless`/`azure-foundry` would otherwise crash at `resolve_role_models` ("unknown model token"); sub-roles stay strict. `grok` is **not** SDAR-paper-validated for any role → emits the advisory `role_model_fidelity` warning on fidelity-critical papers. Code: `foundry_endpoint.py`, `azure_foundry_runtime.py`, the `azure-foundry` branches in `factory.make_runtime`/`grader_transport`, `models.py`, `role_models.py`; `AZURE_FOUNDRY_*` Settings fields in `config.py`.

## Anthropic on Azure Foundry (Opus 4.8 / Sonnet 5) — the reliable-root fix
Root tokens **`opus-foundry`** (Claude Opus 4.8) / **`sonnet-foundry`** (Claude Sonnet 5) reach real Claude weights via the Azure Foundry `…/anthropic` Messages endpoint, `x-api-key=$AZURE_FOUNDRY_API_KEY` — same resource + key as the OpenAI-compatible `azure-foundry`/`grok` provider above, just a different API surface. **CRITICAL gotcha:** the base_url must end at `…/anthropic` — the Anthropic SDK/CLI append `/v1/messages` themselves, so a base ending `…/anthropic/v1` double-`/v1`s to a 404 (`normalize_anthropic_base_url` strips a trailing `/v1`). Wiring is scoped PER-CLIENT, never process-global (rlm root: `clients.get_client` patch; grader/verifier: `AnthropicMessagesClient(base_url=...)`; executor: `runtime.subprocess_env` → `ClaudeAgentOptions(env=...)`) so a co-resident `claude-oauth` root/sub-role is never hijacked — `assert_no_foundry_oauth_coresidency` raises if both appear in one run. Optional env-only overrides: `AZURE_FOUNDRY_ANTHROPIC_ENDPOINT`/`_OPUS`/`_SONNET`. Default-inert unless `opus-foundry`/`sonnet-foundry` is explicitly selected. Code: `backend/agents/runtime/foundry_anthropic.py`, `backend/agents/rlm/_anthropic_foundry_patch.py`.

## Reproduction campaign (`campaign` subcommand — repeat-until-reproduced outer loop)
`python -m backend.cli campaign <paper> --max-llm-usd X --max-gpu-usd Y --max-gpu-hours Z [--max-attempts 6 --mode unattended|checkpoint --campaign-driver live|unified|paired --width 1 --plateau-k 2 --sandbox local --billing-sandbox gcp --gpu-usd-per-hr R --est-gpu-hours 2.0 --run-spec configs/campaign_run_spec.json --scope-spec S --scope-ladder r1,r2 --paper-hint id --resume]` — deterministic outer state machine (INIT → UNDERSTAND → PLAN→LAUNCH→AWAIT→ASSESS→DISTILL→DECIDE loop → `REPRODUCED`/`CONTRADICTED`/`INFEASIBLE`/`EXHAUSTED{stop_reason}`), spec `docs/superpowers/specs/2026-07-01-reproduction-campaign-and-self-improving-harness-design.md` (v2, F1–F16). **Rules:**
- The three money meters are argparse-REQUIRED (no dollar defaults). Exit codes: 0 = terminal reached, 2 = paused (checkpoint/refusal — `--resume` continues), 3 = MONEY-HALT (unwritable spend ledger; nothing new launches). `campaign/{campaign.json,attempts.jsonl}` is a fail-CLOSED ledger (atomic+fsync, write-ahead intent row BEFORE every launch, torn-tail repair on append; corrupt mid-file = halt).
- Split meters map to the real knobs (F2/F3): child `--max-usd` carries the LLM share ONLY; GPU $ via `--max-run-gpu-usd` + `OPENRESEARCH_MAX_RUN_GPU_USD`; gpu-hours enforced STRUCTURALLY by wall-clock co-tightening (no live hours knob); VM ceiling always explicit = effective_wall + 1800s (never the 28h default); runpod children also get `--max-pod-seconds`; `stage_on_gpu` provisioning is billed to the GPU meters; an unenforceable meter ⇒ refuse-unattended (downgrade to checkpoint, PAUSED).
- Trust (F4/F5): assessment hard-quarantine = fabrication-family latest `experiment_runs.jsonl` row / `all_models_failed` / rubric-hash mismatch; soft = validator missing/stale/vetoed. `REPRODUCED` additionally needs `run_level_clean`, full scope rung, and the rubric pin. Champion selection is campaign-owned + guard-filtered; the score-ranked rails (`best_attempt`/`champion_artifact`) NEVER pick the campaign seed — the seed rides `campaign/seed_staging.json` (consumed inside the run by `seed_reference_code`/`floored_target`, only when their env flags are on; marker-with-missing-source fails closed, no scan fallback).
- Clean context (CCRM): directives carry structured artifacts only — a transcript-shaped path (`dashboard_events.jsonl`/`user_messages.jsonl`/`iterations.jsonl`/`repl_state`/`.log`/`prompt`/`transcript`/`attempt_`) in any input FAILS the build; residue is force-archived before every launch (`attempt_isolation.force_archive_incomplete` — the warm-retry heuristic is structurally unreachable under a campaign, F6). Novelty (F10): typed prose-free fingerprint (lineage/rung/repair-kinds/failure-classes/quantized envelope); the current attempt's own intent row is excluded (orphaned-intent relaunch is legal).
- Profile `configs/campaign_run_spec.json`: every key must pass `run_spec_contract.run_spec_key_applies` (INIT round-trips and fails at $0 on any rejected key, F15) and must NEVER carry the driver-owned per-attempt keys (`OPENRESEARCH_SEED_BEST_ATTEMPT`/`OPENRESEARCH_TARGET_BEST_FLOOR`/`OPENRESEARCH_BASELINE_EXTRA_GUIDANCE`/`OPENRESEARCH_MAX_RUN_GPU_USD`) — the child's `_load_run_spec` would clobber the driver's env (INIT fail-closes on overlap).
- Steering (F13): `POST /runs/<id>/campaign/messages` → `campaign/user_messages.jsonl` (ids; count cursor in campaign.json; `set_mode` flips unattended⇄checkpoint at the next loop top). SSE additions: `campaign_started`/`attempt_started`/`attempt_assessed`/`campaign_decision`/`campaign_awaiting_operator`/`campaign_terminal`/`campaign_user_message` (all fail-soft via `_safe_emit`). Leaderboard rows carry a `campaign` key only when `campaign/campaign.json` exists (absent, not null, otherwise).
- DISTILL runs every attempt (mine_lessons + admit_recipe + `ExperienceMemory.record` — its first live caller; admission gates unchanged; each independently fail-soft). Deliverable: `campaign_report.md` + the champion attempt's report (`campaign/champion_final_report.{json,md}` when the champion is the latest assessed attempt); INFEASIBLE/no-assessed terminals write the plan-only `final_report.json{verdict:"plan_only"}` (F14, O_EXCL — never clobbers a real report).
- Drivers: `live` (default, proven path), `unified` (in-process `ReproductionRun`; resume = assess-from-disk — no re-enter API), `paired` (F8 — constructor requires explicit operator initiation; conducts the Phase-1f A/B, sign-off stays operator-owned). Width (F16): `<id>_w<k>` child lineages via the `--project-id` override (register_project ingests the override verbatim; the cmd_reproduce mirror guard is vacuous by construction).
- Campaign flags (default-OFF): `OPENRESEARCH_CAMPAIGN_{MAX_ATTEMPTS(6),MODE,DRIVER,WIDTH(1),WIDTH_SKIP_SCORE(0.5),PLATEAU_K(2),WALL_CLOCK_S,REQUIRE_CPU_TIER}` · `OPENRESEARCH_DOOMED_KILL` (+`DOOMED_{MARGIN(0.30),POLLS(6),MIN_PROGRESS(0.2)}` — pure comparator `doomed_run_comparator.py`, deliberately UNWIRED into any live path) · `OPENRESEARCH_RUBRIC_CANARY` (weight-0 canary leaf appended by rubric-gen; `canary_tripped()` helper; ASSESS wiring is a documented follow-up) · `OPENRESEARCH_SELF_EDIT` (Phase C below).
- **Phase C self-edit (`OPENRESEARCH_SELF_EDIT`, default OFF; F11/F12):** editable surface = `backend/agents/rlm/self_edit_surface.json` ONLY (two bounded numeric retry knobs + one ≤200c guidance suffix); the frozen tier (guards, evidence, rubric+gen, validator, budget, gates, the whitelist file, `harness_self_edit.py` itself) is STRUCTURALLY unreachable — proposals touching it are rejected, test-enforced. Stage order: candidate → shadow (replay over harvested executable `HarnessReplayCase`s; any replay error/stale case/negative-control change = reject, never skip) → canary (operator-supplied paired A/Bs, ≥2 papers × ≥2 seeds, mean delta > grader σ, evidence paths must exist) → default = `apply_default(operator_confirmed=True)` ONLY (no autonomous flip, ever). Stores: `runs/_memory/{harness_proposals,replay}/` + `runs/_memory/harness_overrides.json` (bounds re-validated at apply AND at read). `held_out_gate` stays advisory-lesson-only (F11).
- Live validation is OPERATOR work (money): cheap paper end-to-end first, then SDAR smallest-two on GCP ≥3 paired campaigns (~$300; spec §14/§16). Code: `backend/agents/rlm/{reproduction_campaign,campaign_policy,campaign_types,attempt_assessment,campaign_directives,attempt_driver,understanding_gate,campaign_report,campaign_composition,doomed_run_comparator,harness_self_edit}.py`.

## Feature flags (canonical catalog; default-off unless noted; A/B ≥3 paired SDAR runs before flipping any default)
Env-flag convention used throughout: `os.environ.get("FLAG_NAME", "").strip().lower() in ("1", "true", "yes")`. Canonical prefix is `OPENRESEARCH_*` — `config.py::_apply_legacy_env_aliases` bidirectionally bridges the legacy `REPROLAB_*` prefix to/from `OPENRESEARCH_*` **at import** (fills in whichever is unset, never overwrites an explicit value), so older docs/scripts that still cite e.g. `REPROLAB_BES_ENABLED` or `REPROLAB_LEAF_TRIAGE` resolve to the same setting as the `OPENRESEARCH_*` form — use `OPENRESEARCH_*` in new code/tests (a var set *after* import, e.g. a test monkeypatch, is NOT bridged).

### Navigation accelerator + executor routing
Routes hot-volume `rlm_query`/`llm_query` *navigation* sub-calls off the bundled-CLI transport (orphaned-child wedge, FM-001) onto a cheaper endpoint (canonically OpenAI gpt-5-mini via openai/httpx). Quality-critical grader (`verify_against_rubric`/`propose_improvements`) stays on Sonnet-OAuth: keep `OPENRESEARCH_ACCELERATOR_SCOPE=navigation`, do NOT use `all`. Opt-in: `OPENRESEARCH_ACCELERATOR=endpoint`, `OPENRESEARCH_ACCELERATOR_BASE_URL=https://api.openai.com/v1`, `OPENRESEARCH_ACCELERATOR_MODEL=gpt-5-mini`, `OPENRESEARCH_SUBRLM_OPENAI_TIMEOUT_S=120` (honored by the client; unset → 300s default). Auth: `OPENRESEARCH_ACCELERATOR_API_KEY` is the endpoint credential (default `"local"`); for the `api.openai.com` host it falls back to `OPENAI_API_KEY` automatically when `OPENRESEARCH_ACCELERATOR_API_KEY` is unset (ACC-2). Mode vocabulary: `off`/`auto`/`local`/`runpod`/`azure`/`azure-foundry` (aliases `foundry`/`grok`)/`endpoint` — `azure-foundry` reads `AZURE_FOUNDRY_*` via the canonical resolver (no probe, OpenAI SDK; see Azure Foundry section above). Rollback `OPENRESEARCH_ACCELERATOR=off`. Code: `backend/agents/rlm/accelerator.py`.
**Executor routing (separate flag, same family):** `OPENRESEARCH_EXECUTOR=azure` (aliases `azure-openai`/`aoai`) routes the executor tier (`implement_baseline`) to an Azure OpenAI deployment (`AZURE_OPENAI_API_KEY`/`_ENDPOINT`/`_DEPLOYMENT`; default stays Sonnet; gpt-4o not paper-validated for the executor tier). `OPENRESEARCH_EXECUTOR=azure-foundry` (aliases `foundry`/`grok`/`grok-4.3`) routes it onto `AzureFoundryAgentRuntime` via the canonical `resolve_foundry_credentials`. Both are graceful-fallback-preserving (incomplete creds degrade to the default Sonnet executor, never fail-fast). Code: `backend/agents/runtime/azure_openai_runtime.py`, wired in `backend/agents/rlm/executor.py`.

### Intra-run context map (PEEK-lite)
`OPENRESEARCH_CONTEXT_MAP=on` enables a free deterministic orientation cache: a write hook in `binding.py` unions structured outputs of `understand_section`/`extract_hyperparameters`/`detect_environment` into `runs/<id>/rlm_state/context_map.json` (union-per-field, ≤40 fields/≤8 values/≤8KB incremental ceiling, thread-safe, fail-soft); root reads via `read_context_map()` and (only when the flag is on) is told to consult it before re-deriving. Navigation aid only, never a report source — the evidence backstops remain authoritative: `OPENRESEARCH_EVIDENCE_GATE` (vetoes credited result-leaves lacking on-disk evidence) plus the metric-provenance machinery (`OPENRESEARCH_METRIC_PROVENANCE`, default on, and `OPENRESEARCH_METRICS_COMPLETENESS_CHECK`). Off-state: write no-ops, read returns `{}`, prompt instruction omitted. Code: `backend/agents/rlm/context_map.py`; spec `2026-05-30-intra-run-context-map-design.md`.

### Per-paper negative lessons (MUSE-lite)
`OPENRESEARCH_NEGATIVE_LESSONS=1` enables cross-run per-paper failure memory: `run.py::_finalize` hook (`lesson_distiller.py::mine_lessons`) mines agent-correctable `failure_class` rows from `experiment_runs.jsonl` into `runs/_lessons/<arxiv_id>.json`; the next run of the same `arxiv_id` injects active lessons into implementer guidance via `baseline_implementation.py::_negative_lessons_block`. Guardrails: recurrence-gated promotion (`occurrences>=2`, except `dockerfile_invalid` at 1), classifier-sourced `suggested_fix` (never agent prose), opportunity-aware retirement (staleness>=3, gated on phase reached). Capped ≤5/≤200 chars, advisory only. Needs `ctx.arxiv_id`. Spec: `docs/superpowers/specs/2026-05-30-...` design doc.

### Two-axis reproducibility verdict
`OPENRESEARCH_TWO_AXIS_VERDICT=1` attaches `implementation_verdict`/`replication_verdict` (schema 2) from `rlm_state/{fidelity_certificate,repro_spec}.json` + `code/metrics.json` and projects the legacy verdict from FIDELITY (A4: faithful-but-contradicted ≠ failed). **Upgrade clamp (fail-closed):** those artifacts are root-writable, so a verdict UPGRADE (e.g. gate-downgraded `failed`→`reproduced`) requires ≥1 success-compatible in-process `run_experiment` ledger call — a forged green certificate cannot lift a verdict; downgrades stay free; refused upgrades stamp `reproducibility.verdict_clamped`. ## REPL sandbox safe-builtins patch (spec `2026-05-28-rlm-stability-remediation-design.md`, BUG-LR-011/012)
`rlm`'s `LocalREPL._SAFE_BUILTINS` blocks `eval/exec/compile/input` (correctly — code-execution surface) AND `globals/locals` (incorrectly — pure namespace getters). The latter breaks any root-model script that does `globals().get("report_state", {...})` to persist state across iterations: it raises a bare `TypeError: 'NoneType' object is not callable` that the model cannot diagnose. `backend/agents/rlm/safe_builtins_patch.py` restores `globals`/`locals` at import time; `safe_repl_traceback_patch.py` extends `LocalREPL.execute_code` to include `traceback.format_exc()` in stderr so future REPL failures name the actual line. Both are imported at the top of `backend/agents/rlm/run.py`. **DO NOT restore `eval`/`exec`/`compile`/`input`** — those are the genuine security boundary.

## Forced-iteration policy (Lane H, spec `2026-05-24`; extended `2026-05-28`, BUG-LR-013)
When the root model calls `FINAL_VAR` but the latest `verify_against_rubric` returned `overall_score < target_score` AND `iteration_count < OPENRESEARCH_MIN_RUBRIC_ITERATIONS` (default 2), the orchestrator REFUSES the `FINAL_VAR` and forces the root-loop to continue. The policy ALSO refuses when `latest_rubric_score is None` AND `iteration_count < OPENRESEARCH_MIN_RUBRIC_ITERATIONS` — a root that has not even called `verify_against_rubric` has done strictly less work than one that scored zero, and should not be allowed to ship a `partial` report. Mechanically: `backend/agents/rlm/forced_iteration.py` patches `rlm.environments.local_repl.LocalREPL._final_var` once at import time; a per-run `ForcedIterationPolicy` is pushed onto a thread-local stack via the `forced_iteration_policy` context manager around `rlm.completion`. Each refusal emits a `run_warning` event with `code="forced_iteration"` naming the score/target/iteration numbers and the concrete next step (propose_improvements + implement_baseline + run_experiment). Wall-clock takes precedence: when `ctx.remaining_s() <= 60s` the policy bypasses and the partial report ships. `OPENRESEARCH_MIN_RUBRIC_ITERATIONS=0` disables the policy entirely. Paired with Lane G (`backend/agents/rlm/rubric_guard.py` — the agent-written train.py calls `assert_metrics_schema(...)` at end-of-script; a missing key/artifact raises `RubricGuardFailure` whose JSON-shaped message becomes the next iteration's `repair_context`).

## Universality — supporting "any ML paper"
Paper-agnostic by design. Per-paper customization surface:
- `--paper-hint <arxiv-id>` → `backend/agents/prompts/paper_hints.py::PAPER_HINTS` (optional; add an entry for algorithmic invariants the rubric should enforce — SDAR is the reference shape; missing entry = defaults).
- `--scope-spec` → operator-side narrow/expand of the hint's `default_scope` (models/datasets/seeds).
- `OPENRESEARCH_BASELINE_EXTRA_GUIDANCE` → free-text appended to the implementer prompt (CLI auto-merges `--paper-hint` guidance here, `cli.py:1032`).
- `paper_invariants.py` → deterministic invariants registry (model/env name canonicalization); falls back to no enforcement.
- `--vram-gb <n>` → manual VRAM override (still applies the headroom multiplier).

Out-of-the-box an arbitrary arXiv ID/PDF runs end-to-end: ingest → auto-generated rubric → primitives → sandbox → `verify_against_rubric`. **Quality limit:** the auto-rubric is only as good as the LLM that writes it (no code fix changes this) — strict rubrics catch fakes but reject some good runs, loose rubrics give easy passes; for fidelity-critical papers add a `PAPER_HINTS` entry with regex-based `invariants`.

## Baseline test paper
[SDAR (arxiv 2605.15155)](https://arxiv.org/abs/2605.15155) — **Self-Distilled Agentic Reinforcement Learning** — the canonical baseline; stresses every dimension at once (3 Qwen sizes 1.7B/3B/7B, 3 environments ALFWorld+WebShop+Search-QA, GRPO RL + sigmoid-gated OPSD, 5 baselines, a fine-grained rubric whose leaves inspect the exact invariants `g_t=σ(β·Δ_t)`, stop-gradient on the gate, λ=0.1, β=10, real Qwen weights + real ALFWorld episodes).
