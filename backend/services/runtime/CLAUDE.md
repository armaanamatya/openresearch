> Loaded when working in the runtime/execution layer. Root context: ../../../CLAUDE.md.

## Sandbox config
- `OPENRESEARCH_FORCE_SANDBOX` (default empty) **overrides per-run `--sandbox`** when non-empty — set to `docker`/`local` only to hard-pin a deployment; non-empty makes `--sandbox runpod` a no-op.
- `OPENRESEARCH_RUNPOD_CLOUD_TYPE` — `SECURE` (~$0.69/hr, **default** in `config.py`) vs `COMMUNITY` (~$0.34/hr RTX 4090; set this for the cheapest runs).
- **`--sandbox auto`** resolves to `docker` or `local` ONLY — it never escalates to a paid remote backend (runpod/gcp/azure). Use `--sandbox gcp` or `--sandbox azure` explicitly for cloud GPU runs.
- **Mid-cell GPU-$ heartbeat:** `k8s_job_cell_runner._watch_job` tracks spend during execution; a cell that would breach `--max-run-gpu-usd` mid-flight is killed (`gpu_budget_exceeded`) — cost is bounded even for long-running GKE/AKS cells.
- Full backend matrix + Docker-daemon prerequisite: see **Sandboxes** below.

## Sandboxes
`OPENRESEARCH_DEFAULT_SANDBOX` selects the backend. **Primary clouds: `gcp` (GKE) and `azure` (AKS)** — these are the supported backends for overnight campaigns and production runs. `auto` resolves to `docker` or `local` only. `runpod` is legacy (see below). Local backends: `local` (host subprocesses), `docker` (network/memory/CPU controlled).

### GKE / GCP backend (`--sandbox gke` = `--sandbox gcp`) — PRIMARY
`gke` is a **first-class alias for `gcp`** (`GkeJobBackend`): `SandboxMode._missing_` maps the literal `gke` → the `gcp` member (`backend/agents/execution.py`), so `--sandbox gke`, `--sandbox gcp`, `OPENRESEARCH_FORCE_SANDBOX=gke`, and `OPENRESEARCH_DEFAULT_SANDBOX=gke` (the `default_sandbox`/`force_sandbox` Settings Literals accept `gke`) all resolve to the same backend; a direct `gcp` token never reaches `_missing_`, so the gcp path is byte-for-byte. **Caveat:** CLI + env are the supported `gke` surfaces — the HTTP `POST /runs` body field is typed `SandboxMode` and Pydantic rejects `gke` with 422 (the UI emits `gcp`). `build_environment` is a no-op for gcp/gke (image pre-baked in Artifact Registry). **Preflight:** `scripts/gke_check.sh` (mirrors `runpod_check.sh` — gcloud ADC, GKE cluster reachability, `nvidia.com/gpu` node quota; `--start-pod` is an operator-gated money-spending stub, exit 6); `start.sh` runs it when `OPENRESEARCH_DEFAULT_SANDBOX` ∈ {gcp, gke} (skippable via `START_SKIP_PREFLIGHT=1`), and excludes gcp/gke from the docker-down warning. **Catalog SKUs (`gpu_catalog.py`):** `gcp_l4_24` (g2-standard-8, 1×L4-24GB), `gcp_h100_80` (a3-highgpu-1g), `gcp_h100_80x8` (a3-highgpu-8g, 8×H100-80GB) — provider=gcp/ONDEMAND, paired in `services/pricing/catalog.py::GPU_PRICING`; A100 stays the default ladder, H100 is opt-in (`find_ladder` per-GPU $/hr caps apply; refresh prices quarterly). **Cap reachability:** the single `gcp_h100_80` (≈$11.06/GPU) is unreachable under the default `OPENRESEARCH_MAX_GPU_USD_PER_HOUR=10.0` cap — an operator must raise the cap to use H100. **Multi-GPU GKE cells torchrun-wrap:** the standalone in-pod entrypoint `docker/gke-cell-base/gke_cell_entrypoint.py::build_cell_launch_argv` wraps a >1-GPU cell whose `train_cell.py` carries distributed markers in `torchrun --nproc_per_node=N` (marker-gated — a non-distributed script launched as N procs would race on `metrics.json`; respects `OPENRESEARCH_DISABLE_TORCHRUN_WRAP=1`); it reimplements `primitives._resolve_distributed_launch` inline (the entrypoint can't import the backend). GPU count is plumbed deterministically via `OPENRESEARCH_CELL_GPU_COUNT` (`k8s_job_cell_runner._build_job_manifest`; default 1 → single-GPU + AKS cells byte-for-byte). Live GKE GPU smoke is operator-gated (costs money) — never in CI.

### Local Docker daemon prerequisite
`build_environment` (`primitives.py::build_environment`) short-circuits to a no-op for `local`, `runpod`, `azure`, and `gcp`/`gke` sandboxes (dependencies resolved on the host venv / pod boots `OPENRESEARCH_RUNPOD_IMAGE` over SSH in a per-run venv via `runpod_backend.py` / image pre-baked in ACR or Artifact Registry) — only `docker`/`auto`/unknown run a real local `docker build` and raise `SandboxRuntimeError(backend_unavailable)` without a reachable daemon. `start.sh` preflight-warns on `docker info` for `docker`/`auto` sandboxes only (non-fatal — a per-run `--sandbox` override changes the requirement). Hallucinated `runpod/` FROM tags are normalized to the configured image on the paths that still build — docker/auto (`_normalize_runpod_from_line`, unconditional after the Dockerfile shape guard); on `runpod` the short-circuit itself makes a bad tag harmless. Full workflow + sandbox×prerequisite matrix + troubleshooting: `docs/runbooks/running-the-project.md`. **Gotcha:** a hollow `partial` with `SDK success-with-no-text` is an **auth/SDK** failure (credentials), NOT Docker — read the `/lab` detail-panel blockers to tell them apart.

## RunPod (legacy)
RunPod is a legacy backend. Use `--sandbox runpod` explicitly; it is never selected by `auto`. A one-line notice is logged when RunPod is chosen so operators can confirm the intent. For new campaigns prefer `--sandbox gcp` or `--sandbox azure`.

### RunPod default image
**Current default is `cuda-devel`** (~18 GB) — `config.runpod_image` = `runpod/pytorch:2.1.0-py3.10-cuda11.8.0-devel-ubuntu22.04` (authoritative; supersedes any note claiming a lighter `cuda-runtime` default). The `-devel-` headers are required because common deps JIT-compile against CUDA at install/run time (bitsandbytes, flash-attn, deepspeed) — the lighter `-runtime-` image (~4 GB) breaks a chained `pip install bitsandbytes && python train.py`. Override with `OPENRESEARCH_RUNPOD_IMAGE=...-runtime-...` for the lighter (~4 GB) image only when a paper genuinely compiles no CUDA / needs no CUDA JIT (saves ~5–10 min provisioning + ~$0.50–1.50/run). **Two distinct knobs:** the pod image (what the pod actually boots) defaults `-devel-`; the base of the separate *locally-generated* Dockerfile for `--sandbox runpod` (`environment_detective._RUNPOD_PYTORCH_BASE`) intentionally stays on the lighter `-runtime-` image, since that local build is never used on the pod (see Local Docker daemon prerequisite above) — deliberately kept light.

### Local multi-GPU sandbox (docker-free, spec 2026-05-29)
For a host with local NVIDIA GPUs but no docker/RunPod (e.g. 8×A5000): the `local` sandbox runs experiments as host subprocesses with no image build. `SandboxMode.local` → `LocalProcessBackend`; `build_environment` is a no-op success under `local`; `SandboxConfig.gpu_device_ids` pins GPUs (`LocalProcessBackend` → `CUDA_VISIBLE_DEVICES`, `LocalDockerBackend` → `DeviceRequest(device_ids=...)`). `RunContext.gpu_device_ids` comes from `OPENRESEARCH_GPU_DEVICE_IDS`.
- **Dynamic GPU scheduling:** `backend/services/runtime/local_gpu_allocator.py` — nvidia-smi discovery, excludes GPUs another user holds (used-mem ≥ threshold OR any compute proc), `fcntl`-locked crash-safe leasing by GPU UUID, stale-lease reclaim by PID liveness.
- **Batch scheduler:** `.venv/bin/python scripts/batch_reproduce.py <paper>... --gpus-per-run 4|auto --model claude-oauth` — leases disjoint GPU sets, creates a per-run venv (`runs/<id>/.venv`) with a shared `HF_HOME` weight cache (+ per-run torch/triton/xdg/mpl caches), launches `python -m backend.cli reproduce ... --project-id <id>`, monitors, releases leases (SIGINT-safe). `--gpus-per-run auto` gives one run all currently-free cards. For `local`, `build_environment` is a no-op and the per-run `requirements.txt` is auto-installed into the venv (mirrors the runpod bootstrap).
- **Setup:** needs Python 3.12+ (repo `requires-python>=3.11`) — `uv venv --python 3.12 .venv` (a fresh clone ships no venv); install `backend/requirements.txt` + `requirements-dev.txt` together (resolves cleanly today against `rlms==0.1.1`'s `pytest>=9.0.2` pin).
- **Distributed launch is always-on for multi-GPU** (BEH-1): when `run_experiment` sees >1 visible GPU it wraps training in an `accelerate`/FSDP `torchrun` launcher automatically (`primitives.py::_resolve_distributed_launch`) — no enable flag, only opt-OUT `OPENRESEARCH_DISABLE_TORCHRUN_WRAP=1` for single-process debugging. Multi-GPU leasing therefore implies sharded training, not just N independent cards.
- **Local torch core (env_pin, default ON, `local` only):** the harness owns a coherent cu121 torch/torchvision/torchaudio core — installs it from `OPENRESEARCH_LOCAL_TORCH_INDEX_URL` (default `…/whl/cu121`) **first** and strips the agent's conflicting re-pin from `requirements.txt` into `requirements.hardened.txt` (`primitives.py::_local_core_bootstrap_commands` → `env_pin.py`). `LocalProcessBackend` prepends the venv's bundled CUDA lib dirs — following the per-run venv's `_reprolab_base_inherit.pth` to the base `.venv` where the shared torch physically lives — to `LD_LIBRARY_PATH` so a system CUDA path can't shadow them (guards against an agent-pinned incoherent torch build dying at import, failure class `cuda_shlib_load`, e.g. `libcupti.so.12` failing to dlopen). Pin install is **conditional**: a run venv that already carries a coherent CUDA-≥12.1 torch skips the cu121 reinstall and keeps the host build; the pin installs only on a bare/older-CUDA venv. Escape hatch: `OPENRESEARCH_DISABLE_ENV_PIN=1` (keep the agent's pins) or empty `OPENRESEARCH_LOCAL_TORCH_INDEX_URL` (raw `requirements.txt`). runpod/docker paths unaffected (pin + `LD_LIBRARY_PATH` prepend are `local`-only). Spec: `docs/archive/learn.md` (2026-06-07).

> **Naming note:** env vars are canonically `OPENRESEARCH_*` (what the shipped code reads). `config.py::_apply_legacy_env_aliases` bridges the legacy `REPROLAB_*` prefix to `OPENRESEARCH_*` **at import**, so exporting either prefix before startup is fine — but a var set *after* import (e.g. a test monkeypatch) is NOT bridged, so use `OPENRESEARCH_*` in code and tests. The **cross-process cell-seam vars** (`OPENRESEARCH_CELL_*`) must stay byte-identical on both the runner-inject and `train_cell.py`-read ends (the child process does not import the bridge at all).

### One-GPU-per-cell execution + OOM remediation (spec 2026-05-31)
On a local/docker GPU backend, `run_experiment` routes the training matrix through `backend/agents/rlm/gpu_cell_runner.py::run_matrix` — **one subprocess per cell, pinned to one GPU** (`CUDA_VISIBLE_DEVICES=<one id>`), `min(free_gpus, cells)` in parallel, per-cell OOM shrink-retry (batch-scale 0.5→0.25 + grad-ckpt) — instead of the monolithic `commands.json`/`python train.py` path. The route is **gated on the agent emitting `code/cells.json`** (the matrix manifest — the ONLY place the baseline axis lives; `ScopeSpec` is model×dataset×seed) **+ `code/train_cell.py`** (a single-cell trainer reading `OPENRESEARCH_CELL_PARAMS`/`OPENRESEARCH_CELL_OUTPUT_DIR` + argv `--cell-id`/`--output-dir`, honoring `OPENRESEARCH_CELL_BATCH_SCALE`/`OPENRESEARCH_CELL_GRAD_CHECKPOINT`, writing a FLAT per-cell `metrics.json`). Missing either manifest → **fail-soft to the legacy monolithic path** (non-SDAR papers unaffected). **Route retention (default ON):** a repair pass that drops `cells.json` while keeping `train_cell.py` gets the manifest auto-restored from `rlm_state/last_cells.json` (+ `cells_manifest_restored` warning); cells-route failure classes (`cell_execution_error`/`cell_smoke_failed`), a missing trainer, or `OPENRESEARCH_CELLS_ROUTE_RETENTION=0` degrade to an advisory `cells_manifest_dropped` warning — the monolithic regression is loud or impossible, never silent. Mutually exclusive with `_resolve_distributed_launch` (torchrun). The cell scheduler is shared with the Azure K8s path via `backend/agents/rlm/cell_scheduler.py`.

`describe_capacity(ctx) → GpuCapacity` (`backend/services/runtime/gpu_capacity.py`) is the backend-agnostic budget source (local real; runpod/brev real-ish; azure plan-aware via `_describe_azure` — AKS node-pool count + `gpu_plan.json`, `num_gpus` from `azure_max_nodes`). Three stages: **PREVENT** — `cell_matrix.capacity_gate` drops cells whose `est_vram_gb × headroom` exceeds the per-GPU budget → `scope.gaps`/`scope.models_skipped` (24 GB ⇒ smallest-two, never the 7B); `cell_matrix.dataset_url_preflight` HEAD-probes `cells.json::dataset_url` and drops a **confirmed** 404 → `scope.gaps` (fail-soft: a transient blip never drops a live env). **PLACEMENT** — `run_matrix`. **AGGREGATE** — `cell_matrix.aggregate_cell_metrics` synthesizes the canonical `per_model[model_key][env][baseline]` leaf shape the leaf scorer + ~8 postflight guards consume, persisted to `code/metrics.json` + `code/outputs/<run_id>/metrics.json` (treats `skipped`/`timeout` cells correctly for resume + reliability). **A ran cell never vanishes from the aggregate:** `cell_matrix.normalize_cell_axes` derives missing `model_key`/`env`/`baseline` from agent-vocabulary synonyms (`dataset`/`variant`/…, falling back to the cell id) at manifest load, and aggregation derives as a second layer instead of silently skipping; derivation emits a `cell_axes_derived` run_warning + `contract_warnings` so the agent emits explicit axes next iteration. **STOP** — when every run cell OOMs after shrink-exhaustion (`oom_shrink_exhausted`) or all cells are dropped (`capacity_exhausted`), `run_experiment` returns a terminal `stop_reason`; `run.py`'s tool wrapper calls `policy.note_terminal_failure(...)` so `forced_iteration` accepts the next `FINAL_VAR` — **stop + report, NO re-OOM loop** (do NOT reuse `silent_oom`, which correctly stays repairable for a *single* caught OOM). `final_report.json.stop_reason` carries the structured reason. `cell_matrix.py` is pure (stdlib-only) and unit-tested against a real on-disk `metrics.json` sample.

Copyable helpers the agent's generated code imports are auto-copied into `code/` by `run_with_sdk` (`gpu_cell_runner.py` + `cell_scheduler.py` + `sdar_env_base.py`, all zero-non-stdlib-dep — a real file copy, mirroring the `rubric_guard.py` emit pattern). `sdar_env_base.BaseEnv`/`AgenticEnv` are ABCs (`build_student_prompt`/`build_teacher_prompt`) so a `*Env` missing them fails at **construction** (cell start), not mid-grid; `preflight_ast._check_env_interface_contract` (recursive `rglob`, self-scoping) rejects a non-subclassing `*Env` *before* the grid runs. Full design + per-component commit map: `docs/superpowers/specs/2026-05-31-oom-gpu-capacity-remediation-design.md` and `docs/runbooks/2026-05-31-oom-gpu-remediation-handoff.md`.

### Execution reliability — streaming + stall + finalize-on-timeout (spec 2026-06-08, `local`-scoped + flag-gated)
On the `local` sandbox, `run_experiment` STREAMS subprocess output to `runs/<id>/code/.exec_live.log` (+ a `.exec_heartbeat.json` sidecar; surfaced as periodic `experiment_progress` SSE) so a long GPU run is observable live (`tail -f code/.exec_live.log`) instead of buffering silent. A generous stall window (`OPENRESEARCH_EXPERIMENT_STALL_S`, default 3600s, `0` disables) kills only a GENUINE hang as `exec_stalled` — liveness = OR of {new output line, ckpt/`metrics.json` mtime bump, GPU-util (`OPENRESEARCH_EXPERIMENT_GPU_LIVENESS=1`), process-tree CPU-util}, distinct from the hard wall-clock budget cap (`exec_timeout`). A timeout/stall now FINALIZES completed work: the on-disk partial `metrics.json` is scored (failure class `partial_timeout`, repairable), never zeroed. All fail-soft; runpod/docker exec paths byte-for-byte unchanged. Full design: `docs/runbooks/2026-06-08-execution-reliability-redesign-handoff.md`.

**Finalize-time freshness re-grade (default ON):** when the on-disk `code/metrics.json` lands materially after the last `verify_against_rubric` (`rubric_evaluation.json` mtime) AND the recorded grade is below target, `run.py::_finalize` re-grades the COMPLETE evidence via the leaf scorer and adopts it only if strictly higher (best-of-run MAX semantics). One extra LLM call, gated to the stale-and-below-target shape only; wired into ALL finalize paths (shared `regrade_and_emit` on `_finalize`/`_finalize_fatal_primitive_abort` + `regrade_for_hard_stop` on the no-ctx watchdog/SIGTERM salvage, `llm_client` threaded through `_arm_watchdog`/`_install_sigterm_finalizer`); ALWAYS emits the fire/skip reason (`finalize_regrade_adopted`/`_skipped`/`_hardstop`); `REPROLAB_FINALIZE_REGRADE=0` disables (this flag is genuinely `REPROLAB_`-prefixed in the code — it reads `os.environ` directly and is not bridged); `backend/agents/rlm/finalize_regrade.py`. **Hard-stop salvage:** the watchdog/SIGTERM finalizer (`run.py::_hard_stop_with_report`) salvages the run's earned evidence instead of shipping a scoreless `failed`: best-of-run rubric floor from dashboard events, verdict reconciled (≤`partial`), structured `stop_reason` (`wall_clock_watchdog`/`sigterm`), and `write_final_report_rlm`'s rubric_evaluation merge fills `overall_score`/`target_score`/`meets_target` when the report carries unscored `None` defaults — safe because attempt isolation archives `rubric_evaluation.json`/`rubric_tree.json` + telemetry sidecars per attempt (`attempt_isolation._ARCHIVE_FILES`). Disk hygiene: `scripts/gc_runs.py` (dry-run by default) reclaims per-cell `datasets/` copies + weight files; `.preserved` runs are skipped.

### Multi-cloud provisioning & compute (2026-07-01, Phase 1a–1e; all UNWIRED/default-OFF except `OPENRESEARCH_CLOUD_FAILOVER`)
Forward-looking paper-agnostic provisioning + a unified compute seam. Spec `docs/superpowers/specs/2026-07-01-paper-agnostic-multicloud-reproduction-and-self-improvement-design.md`. (Phase 1e — `OPENRESEARCH_EXPERIENCE_MEMORY` — is documented in `../../agents/rlm/CLAUDE.md`.)
- **1a — env provisioning seam:** `env_adapters/` (`EnvironmentAdapter` + `Alfworld`/`WebShop`/`SearchQa` adapters) over `asset_cache.py` (`AssetCache`, fcntl-locked crash-safe). `env_cache.py` is now a thin facade (`EnvCacheManager`/`provision_scope` delegate; warm-cache filenames/keys unchanged) — add a new env as a NEW adapter, not an `EnvCacheManager` method.
- **1b — pre-GPU-lease gates (deterministic, UNWIRED):** `feasibility_triage.py` (`FeasibilityTriage` PROCEED/DOWN_SCOPE/PLAN_ONLY + `estimate_scope_cost`), `run_plan.py` (`RunPlan.required_assets`), `RunBudget.max_gpu_hours`.

- **1d — credentials + assets + CPU-warm-disk (UNWIRED):** `CredentialBroker` (`credential_broker.py` — canonical os.environ→Settings secret resolver + `redact_env`/`redact_text`; no raw `.env` on the wire, never logs a value into a bundle); generic `AssetResolver` (`asset_resolver.py` — resolves a 1b `RequiredAsset` by kind; unresolved/gated → a verified `Exclusion`, never fake-ok; REUSES `dataset_recipes.find_recipe`); `VmComputeProvider.cpu_warm_disk_then_gpu_attach` (a cheap CPU VM warms the persistent cache disk + detaches, the GPU VM re-attaches it, same-zone-locked fail-soft; `stage_on_gpu` default stays byte-identical).
