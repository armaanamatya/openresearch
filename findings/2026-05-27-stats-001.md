## 8. Narrative findings

_Appended by current session — no extra API cost — after reading sections 1–7 above._

### Finding 1 — `claude_agent_sdk` async cleanup bug is the #1 reproduction killer 🔴

**Severity:** critical | **Fix class:** code/infra | **Runs affected:** 5/8 (62%)

Clusters 1 + 2 are the same root cause: `RuntimeError: aclose(): asynchronous generator is already running` paired with `asyncgen: <async_generator object InternalClient._process_query_inner at 0x...>`. **37 occurrences in 5 runs each** — every run that touched the SDK hit it repeatedly during shutdown. Cluster 3 (closed event-loop messages, 31 occurrences across 5 runs) is downstream of the same issue: when the SDK can't cleanly close one async generator, the next loop is already closed by the time we try.

This is **not** a prompt problem. No GEPA / HALO / SkillOpt mutation can fix it because it manifests *outside* the RLM root's REPL — inside the sub-agent SDK plumbing. Filed evidence: every `prj_2*`, `prj_5*`, `prj_7*`, `prj_9*` stderr tail.

**Suggested fix surface:** `claude_agent_sdk` integration layer, specifically around how we exit nested `async for` over `client.process_query(...)`. Likely needs an explicit `async with anyio.CancelScope():` or a guard against double-cleanup. Worth opening upstream issue if the bug is in the SDK itself, not our caller.

### Finding 2 — OOM (exit code -9) kills 38% of runs 🔴

**Severity:** high | **Fix class:** infra | **Runs affected:** 3/8 (38%)

Cluster 8 (`Exception: Command failed with exit code -9 (exit code: -9)`) recurs in 3 runs, all on Docker sandbox. Exit code -9 = SIGKILL = kernel OOM killer. Each killed run terminated within 1.5–28 minutes with zero successful iterations.

Two plausible memory sinks given current code:
1. PDF text loading — `parsed_full_text.txt` for the canonical test paper is 137 KB but `raw_paper.pdf` is 9.9 MB; if both load into memory inside the container with the model context simultaneously, peak RSS is bounded only by the container limit.
2. Sub-agent Sonnet calls accumulating message history without bounded windows.

**Action:** instrument peak RSS via `/proc/self/status` snapshot at primitive boundaries; document a Docker memory floor (e.g., `--memory=8g` minimum) in CLAUDE.md; consider chunked paper loading or memory-mapped reads.

**Phase 3+ implications:**

2. **SkillOpt (Phase 5) drops to lowest priority.** Even if SkillOpt's "+24.8 agentic-loop bonus" is real, it acts on the improvement loop — which 7/8 runs in our corpus never reach.
3. **GEPA polish (Phase 2) remains correct work** — it's cheap, contained, and unblocks future evaluations once runs live long enough to exercise prompts.
